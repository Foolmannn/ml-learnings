# Framing a Machine Learning Problem

**Framing a machine learning (ML) problem** is the process of converting a real-world problem into a well-defined ML task. It is one of the most important steps in any ML project because a poorly framed problem often leads to poor results, regardless of how advanced the algorithm is.

---

# Definition

Machine learning problem framing is the process of defining:

* What problem needs to be solved.
* What data is available.
* What should be predicted.
* Which type of ML approach should be used.
* How success will be measured.

**Goal:** Transform a business or real-world objective into an ML task.

---

# Steps in Framing an ML Problem

## 1. Understand the Business Problem

Before using any ML algorithm, clearly understand the objective.

Ask questions like:

* What is the goal?
* Why is this problem important?
* Who will use the prediction?
* What impact will wrong predictions have?

### Example

Business Problem:

> A bank wants to reduce loan defaults.

ML Problem:

> Predict whether a customer will default on a loan.

---

## 2. Determine Whether ML is Needed

Not every problem requires ML.

Sometimes simple rules work better.

### Rule-based Example

```
IF age < 18
Reject application
```

No ML needed.

### ML Example

Predicting house prices depends on many variables:

* Location
* Area
* Bedrooms
* Market trend
* Nearby schools

A simple rule cannot solve this.

ML is appropriate.

---

## 3. Define the Target Variable

The target (label/output) is what the model should predict.

Examples:

| Problem                | Target Variable        |
| ---------------------- | ---------------------- |
| House price prediction | House price            |
| Email filtering        | Spam or Not Spam       |
| Disease prediction     | Disease present or not |
| Sales forecasting      | Future sales           |
| Student performance    | Final marks            |

Example:

```
Input:
Area = 1200 sq ft
Bedrooms = 3
Location = City

Output:
Price = $180,000
```

Target = Price

---

## 4. Identify Input Features

Features are the variables used to make predictions.

### Example (House Price)

Features:

* Area
* Number of bedrooms
* Bathrooms
* Age of house
* Garage
* City
* Nearby schools

Target:

```
Price
```

---

## 5. Collect Data

Determine:

* What data is available?
* How much data exists?
* Is it labeled?
* Is it accurate?
* Is it balanced?

Example:

| Area | Bedrooms | Age | Price  |
| ---- | -------- | --- | ------ |
| 1200 | 3        | 10  | 150000 |
| 1500 | 4        | 5   | 220000 |
| 1000 | 2        | 15  | 120000 |

---

## 6. Select the Type of ML Problem

This is one of the most important decisions.

### A. Regression

Predicts continuous values.

Examples:

* House prices
* Salary prediction
* Temperature
* Stock prices

Output:

```
Price = $220,000
```

Continuous number.

---

### B. Classification

Predicts categories.

Examples:

* Spam / Not Spam
* Fraud / Genuine
* Disease / Healthy
* Pass / Fail

Output:

```
Spam
```

or

```
Healthy
```

---

### C. Clustering

No labels.

Goal:

Group similar data together.

Example:

Customer segmentation.

---

### D. Recommendation

Predict what users may like.

Examples:

* Netflix movies
* Amazon products
* YouTube videos

---

### E. Ranking

Sort items according to relevance.

Examples:

* Google search
* Product ranking

---

### F. Time Series Forecasting

Predict future values using past observations.

Examples:

* Weather
* Electricity demand
* Sales forecasting

---

## 7. Choose Evaluation Metrics

Different problems require different metrics.

### Regression

* MAE
* MSE
* RMSE
* R² Score

Example:

Actual:

```
100
```

Predicted:

```
98
```

Small error → good model.

---

### Classification

* Accuracy
* Precision
* Recall
* F1 Score
* ROC-AUC

Example

```
Actual:
Spam

Prediction:
Spam
```

Correct prediction.

---

## 8. Understand Constraints

Consider:

* Prediction speed
* Memory usage
* Cost
* Privacy
* Interpretability
* Hardware limitations

Example:

A medical diagnosis model should not only be accurate but also explain why it made a prediction.

---

## 9. Prepare the Dataset

Split into:

```
Dataset
   │
   ├── Training Set
   ├── Validation Set
   └── Test Set
```

Typical split:

* Training: 70%
* Validation: 15%
* Test: 15%

---

## 10. Define Success Criteria

Success should be measurable.

Examples:

Instead of:

> Improve sales.

Use:

> Increase sales prediction accuracy above 90%.

or

> Reduce fraud loss by 30%.

---

# Types of ML Problem Framing

## 1. Supervised Learning

Training data contains labels.

Example:

```
Image → Cat
Image → Dog
```

Goal:

Predict labels.

Examples:

* Price prediction
* Spam detection
* Disease prediction

---

## 2. Unsupervised Learning

No labels.

Goal:

Find hidden patterns.

Example:

Customer segmentation.

---

## 3. Semi-supervised Learning

Small amount of labeled data.

Large amount of unlabeled data.

Example:

Medical images.

---

## 4. Reinforcement Learning

Agent learns by interacting with an environment.

Examples:

* Self-driving cars
* Robotics
* Game playing

# Common Mistakes in Problem Framing

* Choosing the wrong ML task (e.g., using classification instead of regression).
* Defining an unclear or incorrect target variable.
* Using irrelevant or low-quality features.
* Ignoring business constraints and stakeholder needs.
* Using inappropriate evaluation metrics (e.g., accuracy for highly imbalanced datasets).
* Collecting insufficient or biased data.
* Assuming ML is needed when a simple rule-based solution would suffice.

## Key Takeaways

* Problem framing is the foundation of every ML project.
* Start with the business objective, then translate it into a clear ML task.
* Clearly identify the **target variable**, **input features**, and **available data**.
* Choose the appropriate ML approach (regression, classification, clustering, recommendation, etc.) based on the desired output.
* Define suitable evaluation metrics and success criteria before training any model.
* A well-framed problem increases the likelihood of building an accurate, useful, and deployable machine learning solution.
